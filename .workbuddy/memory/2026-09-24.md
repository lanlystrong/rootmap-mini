# 2026-09-24 工作日志

## 服务端代码审查（rootmap-mini/server）
对 `src/` 全量源码做了代码审查（配置 / 内容 API / 鉴权 / 带鉴权数据端点）。核心结论：

### 高优先级
1. **内容真源矛盾（架构性）**：线上服务器 `app.js:26` → `content.js:loadContent()` 启动时从静态文件 `miniprogram/data/index.js` **一次性读入内存**（`require('../../miniprogram/data/index')`），并不读 MySQL。`src/contentStore.js` 的 `readDataset`（从 MySQL 读）**只被 `scripts/content-import.js` 与 `test/db-content.test.js` 引用**，线上路由完全没用它。而 `db.js` 注释声称"数据库是内容的唯一真源"——实现与注释/README 不符。
   - 影响：上一轮"新增词已即时生效、无需重启"的说法**错误**。正确流程是重跑 `generate-content.js` 再生 `index.js` + **重启服务**才生效；MySQL 内容库对线上请求无影响。
   - 建议：要么把 `readDataset` 接进 `loadContent`（让 DB 成为真源 + 加重载机制实现"免重启"），要么修正注释、明确文件为构建产物/真源。

### 中优先级
2. `/families/:rootId` 按词性分组失效：`contentRouter.js` 用 `word.pos`，但交付集单词**无顶层 `pos`**（1450/1450 都没有，词性只在 `senses[].pos`），全部落入"其他"。
3. `content.js` `meta.version` 写死 `'0.1.0'`、`checksum` 只基于 id 集合哈希 → `/api/content/meta`、`/checksum` 无法反映释义/音标/例句的内容变更，客户端只能靠 id 增减判断更新。
4. `/api/events` 只存 `type/word_id/q/at`，丢弃 `correct/a/interval_hours`；`word_progress`/`root_progress`/`next_review` 全 API 从不更新 → README 的 SM-2 复习调度未接通（事件仅作原始日志）。

### 低优先级 / 安全
5. `.env` 已被 git 忽略（密钥未入库，安全）；但 `server.js`/`app.js` **未加载 dotenv**（仅 `init-db.js` 加载），线上用代码默认值（`rootmap_1`，与导入库一致；`.env` 里的 `rootmap` 反而不生效）。`.env.example` 仍带弱默认 `JWT_SECRET`/`MYSQL_PASSWORD`。
6. `authRouter.js:28` JWT 默认密钥 `'rootmap-secret-key'` 与 `.env` 的 `rootmap-secret-key-2024` 不一致；线上 `authRequired` 走 `sessions` 表随机令牌，`verifyToken`(JWT) 是死代码；README 称"JWT 认证"与实现不符。
7. `middleware.js` CORS `cors()` 无参 = 全域名 `*` 开放（含鉴权端点）；JSON API 下危害有限但建议收紧。
8. `db.js` `migrateLegacyUsers` 用 `users_backup_${Date.now()}` 两次（CREATE 与 SELECT）时间戳不同 → 备份表名不匹配（仅旧库迁移路径触发）。

### 正向结论
- `eventsRouter`/`statsRouter` 输入校验严格、全参数化查询，无注入风险。
- `contentStore` 的读/写/指纹/逐字段 diff 只保留一份、规范化 JSON 键序，设计严谨。
